Yonsei Policy Deployment Plan

Run the robot policy server inside a Yonsei SLURM GPU job, expose it through a public proxy layer, and give organizers a stable WSS endpoint.

SLURM GPU job Reverse SSH tunnel Caddy or nginx TLS VM, personal computer, or tunnel service

Architecture

What Runs Where

Organizers

They connect to the public WSS endpoint, send binary msgpack observations, and receive action chunks.

URL: wss://policy.yourdomain.com
Header: Authorization: Api-Key <token>

Public proxy layer

This can be a cloud VM, an always-on personal computer, or a managed tunnel service. It terminates TLS and forwards to the policy server path.

Caddy/nginx: 443 -> 127.0.0.1:18000

Yonsei GPU job

The SLURM job starts the policy server and opens the outbound SSH tunnel to the proxy host.

policy server: 127.0.0.1:8000
ssh -R 127.0.0.1:18000:127.0.0.1:8000

Proxy Host Options

Option A: Cloud VM

Operationally cleaner. Usually has a public IP, stable uptime, and simple firewall rules.

  • Create a Linux user, for example deploy.
  • Add Yonsei's public SSH key to ~deploy/.ssh/authorized_keys.
  • Install Caddy or nginx.
  • Open public ports 80 and 443.
  • Keep 18000 private to localhost.

Option B: Personal Computer

Viable for a quick PoC if your computer can act like a public server and stay online.

  • Disable sleep and keep the machine plugged in.
  • Run an SSH server and Caddy/nginx.
  • Forward router port 2222 to computer port 22.
  • Forward router ports 80 and 443 to the computer.
  • Use dynamic DNS if your public IP changes.
  • Confirm you are not behind CGNAT.
CGNAT warning: if you are on campus Wi-Fi, apartment Wi-Fi, hotel Wi-Fi, or an ISP connection using CGNAT, direct router port forwarding may not work. In that case, consider Cloudflare Tunnel, ngrok, or Tailscale Funnel, but confirm the organizers accept that endpoint style.

Provider Examples

Cloud VM providers

Use these if you want a normal Ubuntu box with SSH, Caddy/nginx, and a stable public IP.

  • DigitalOcean Droplet
  • AWS Lightsail or EC2
  • Google Cloud Compute Engine
  • Azure Virtual Machine
  • Hetzner Cloud
  • Vultr
  • Akamai Linode
  • Oracle Cloud Free Tier VM

Managed tunnel services

Use these if you want outbound-only forwarding and may not want to rent a VM.

  • Cloudflare Tunnel: cloudflared creates outbound connections to Cloudflare and maps a public hostname to a local service.
  • ngrok: the ngrok agent creates an outbound tunnel and gives you an HTTPS URL for a local port; stable domains may depend on account/plan.
  • Tailscale Funnel: exposes a local service on a Tailscale device to the broader internet over HTTPS.
  • zrok or similar tools: useful for PoCs, but check reliability and organizer acceptance.
Important distinction: if the managed tunnel agent runs on your personal computer, Yonsei still needs some way to reach that computer unless the reverse SSH tunnel is replaced. If the managed tunnel agent runs directly inside the SLURM job, it can expose 127.0.0.1:8000 directly and skip the reverse SSH hop, but then the endpoint only exists while both the job and tunnel agent are running. Confirm cluster policy and organizer acceptance before relying on that path.
Evaluator compatibility: the organizers should not need to install anything for Cloudflare Tunnel, ngrok, or Tailscale Funnel. If the tunnel exposes a normal public wss:// endpoint and transparently forwards WebSocket traffic to our policy server, their OpenPI-style WebSocket client should see the same protocol as a direct server. The tunnel must preserve WebSocket upgrades, binary frames, custom Authorization headers, large image observations, and long-lived connections. Avoid tunnel modes that add browser interstitial pages or require the evaluator to join a private network.

Cost Comparison

For a short PoC, managed tunnels can be zero-cost or cheaper than a VM. For an overnight competition endpoint, a small VM is still inexpensive and often more predictable.

Option Approximate Cost What You Get Main Caveat
Cloudflare Tunnel Often $0/mo for this kind of public app tunnel; Cloudflare Tunnel is available on all plans, and Cloudflare has a free plan. No public IP, no inbound ports, public hostname mapped to a local service through cloudflared. Usually needs a domain managed by Cloudflare for a stable hostname. If the agent runs inside SLURM, the endpoint dies with the job.
ngrok $0/mo free tier with tight limits; $10/mo Hobbyist monthly; Pay-as-you-go usage pricing for production-style needs. Very fast setup, HTTPS URL, outbound-only agent, good for demos and webhooks. Free tier limits include request/data caps and an interstitial page. Paid ngrok can cost more than a tiny VM if traffic grows.
Tailscale Funnel $0/mo on Personal for non-commercial use; Standard is $8/user/mo, Premium is $18/user/mo. Public HTTPS exposure for a local service on a Tailscale device. Funnel is still documented as beta. Personal plan is explicitly non-commercial; check fit for the competition.
DigitalOcean Droplet Starts around $4-$6/mo; billed by short intervals with a monthly cap. Normal VM with SSH, Caddy/nginx, public IP, firewall, predictable endpoint. Costs more than a free tunnel, but the absolute cost is small and operationally simple.
AWS Lightsail Linux/Unix bundles start at $5/mo with public IPv4, or $3.50/mo IPv6-only. Simple AWS VPS with static IP and DNS features bundled. AWS account setup and networking are more ceremony than the tunnel tools.
Hetzner Cloud Entry cloud servers are roughly €3.99/mo or $4.99/mo after the April 2026 adjustment, excluding VAT. Cheap VM with strong price/performance, especially in Europe. Regional availability and account approval can be friction. Prices are changing in 2026, so verify before buying.
Akamai Linode Nanode 1 GB is $5/mo. Normal VM with included transfer and straightforward networking. Same VM maintenance burden as other VPS providers.
Practical read: Cloudflare Tunnel is likely the cheapest serious managed-tunnel candidate if the organizers accept it. Tailscale Funnel can be free for personal/non-commercial use, but its fit depends on rules and beta status. ngrok is easiest for a demo, but its free limits and paid pricing can become less attractive than a $4-$6/month VM. A tiny VM is not the cheapest in pure dollars, but it is predictable and still inexpensive.
Why not host directly on the SLURM cluster? The GPU server runs on a compute node allocated by SLURM, not on a stable public host. Compute nodes usually do not have routable public inbound ports, and their hostname can change every time the job is scheduled. Login nodes should not run long-lived GPU inference services, and administrators may kill heavy or long-running login-node processes. Even if a compute node could bind a port, the service would disappear when the SLURM job ends, and you would still need public TLS, firewall rules, and a stable DNS name. The proxy host keeps the public endpoint stable while the Yonsei job only makes an outbound SSH connection.

Values You Need To Supply

Variable Meaning How To Get It
POLICY_SERVER_API_KEYS Secret token organizers send in the WebSocket Authorization header. openssl rand -hex 32
TUNNEL_SSH_TARGET SSH destination for the proxy host. deploy@vm.example.com or zach@home-proxy.example.com
TUNNEL_SSH_PORT SSH port if your proxy host does not expose SSH on port 22. Use 2222 if your router forwards public 2222 to local 22.
TUNNEL_SSH_KEY Private SSH key on Yonsei used to log into the proxy host. ~/.ssh/policy_tunnel, generated with ssh-keygen.
TUNNEL_REMOTE_PORT Localhost port on the proxy host created by the reverse tunnel. Keep default 18000.
POLICY_SPEC Python import path for the policy class. Use examples.echo_policy:EchoPolicy for the first PoC.
POLICY_KWARGS Constructor values for the real policy. Leave unset for echo PoC. Later set checkpoint path and device=cuda:0.

Setup Sequence

On Yonsei

  1. Create the Python environment.
  2. Generate a tunnel SSH key.
  3. Copy the public key to the proxy host.
  4. Create an untracked .env.
  5. Submit the SLURM job.
cd /home/tangzach/forwarding-test
python -m venv .venv
.venv/bin/pip install -r requirements.txt

ssh-keygen -t ed25519 -f ~/.ssh/policy_tunnel -C policy-tunnel
cat ~/.ssh/policy_tunnel.pub

cp deploy/yonsei.env.example .env
chmod 600 .env
vi .env

On Proxy Host

  1. Add the printed Yonsei public key to the SSH user's authorized_keys.
  2. Install and configure Caddy or nginx.
  3. Point DNS at the proxy host if you have a domain.
  4. Open public 80 and 443.
  5. Keep 18000 private.
policy.yourdomain.com {
    reverse_proxy 127.0.0.1:18000
}

Minimum .env For Echo PoC

export POLICY_SERVER_API_KEYS="replace-with-openssl-rand-token"
export TUNNEL_SSH_TARGET="deploy@YOUR_PROXY_PUBLIC_IP_OR_DOMAIN"
export TUNNEL_SSH_KEY="${HOME}/.ssh/policy_tunnel"

export TUNNEL_REMOTE_BIND="127.0.0.1"
export TUNNEL_REMOTE_PORT="18000"
export POLICY_SPEC="examples.echo_policy:EchoPolicy"
export PYTHON_BIN="/home/tangzach/forwarding-test/.venv/bin/python"
If using a home computer behind router forwarding, add export TUNNEL_SSH_PORT="2222" if public port 2222 forwards to the computer's SSH port 22.

Submit And Test

Submit job

mkdir -p logs
source .env
sbatch deploy/yonsei_policy_server.sbatch

squeue -u "$USER"
tail -f logs/policy_server.<JOBID>.out

Test endpoint

# From the proxy host
curl -i http://127.0.0.1:18000/healthz

# From the public internet
curl -i https://policy.yourdomain.com/healthz

# WebSocket protocol test
PYTHONPATH=. python scripts/ping.py \
  --host wss://policy.yourdomain.com \
  --api-key "$POLICY_SERVER_API_KEYS"

Switch From Echo To Real Policy

After the echo-policy networking PoC works, update .env to load the real policy.

export POLICY_SPEC="examples.my_policy:MyPolicy"
export POLICY_KWARGS="checkpoint_path=/lustre/${USER}/checkpoints/policy.pt device=cuda:0"
Keep device=cuda:0. SLURM sets CUDA_VISIBLE_DEVICES, so cuda:0 maps to the GPU assigned to the job.
